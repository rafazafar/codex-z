# Codex Desktop 26.908 Request Manager wrapper

This records failed codex-z connection checks after Desktop `26.908.40834` (build `8881`) wrapped Composer Fiber Request Manager in a hook object. It is not a stable internal Desktop API contract. Repeat live probes after updates.

## Observed environment

- Codex Desktop: `26.908.40834` / build `8881`
- Codex Framework: `152.0.7977.83`
- codex-z: `0.7.0`, macOS DMG
- Path: local Host, `app://-/index.html` main window

## User symptoms

Renderer injection and Settings worked. The Renderer Adapter stayed at installing with `draft-routing-policy-unavailable`. Pi, Grok, DeepSeek Harness, and other external Agent connection checks failed:

```text
error.code: internalError
error.message: Renderer Model request manager is unavailable
retryable: true
stage: request
```

`window.__codexZDraftPrewarmPolicyV1` was absent. This was not an individual Harness installation/Account problem.

## Cause

In `26.814`, hook state **itself** was the outer manager:

```text
hook.memoizedState = outer manager
  - requestClient -> inner bridge (sendRequest / prewarmThreadStart / enqueueRequest)
  - sendRequest
  - prewarmedThreadManager.discardAllPrewarmedThreads
  - getHostId()
```

`26.908.40834` put it in a hook wrapper:

```text
hook.memoizedState = {
  hostId: "local",
  manager: <original outer manager>,
  status: "ready"
}
```

Read-only live probes found zero matches with the existing finder and one after unwrapping `.manager`. `executionTargetHostId` / `permissionsHostId` both were `local`. Inner bridge `sendRequest`, `prewarmThreadStart`, `enqueueRequest`, and `discardAllPrewarmedThreads` remained. Compressed class names cannot identify the object.

Draft routing could not install; the Adapter could not reach `ready / request-bridge`. `currentModelClient()` failed in the request stage.

The finder had no diff between codex-z `0.6.2` and `0.7.0`. Desktop Fiber relationships changed; codex-z 0.7.0 did not introduce the search failure.

After Request Manager discovery, external Agent menus opened, but Grok/other selection showed `Models unavailable` / permissions unavailable with title `External configuration could not be applied to the Composer`. Another 26.908 contract changed: Composer Fiber memo-cache `client-new-thread:` identity was no longer always a seven-slot atom wrapper.

```text
Old: length 7; value[2] draft id; value[3] === value[5] === value[6]; get() contains modelSettings
New: same draft id appears at least twice in longer tuples (observed length 13 [3,5,6] and length 19 [2,7])
```

Seven-slot-only search made `findComposerModelTarget` return `null`; drafts could not write Composer configuration. Search must accept both seven-slot atoms and memo tuples with repeated `client-new-thread:` strings. Multiple different draft IDs still require rejection.

## Applicable code

| File | Role |
| --- | --- |
| `packages/desktop-control/src/renderer-draft-prewarm-policy.ts` | Installation-time CDP finder accepts hook state itself or `.manager` only after existing API-shape validation. |
| `packages/renderer-extension/src/versioned-renderer-adapter.ts` | Adapter fallback unwraps Request Manager; draft identity accepts seven-slot atoms and repeated `client-new-thread:` memo tuples. |

Search still rejects unsafe matches: hostId must be nonempty/unique; `prewarmedThreadManager` is required. No fallback through compressed class names/function source.

## Validation

Focused tests cover:

- Direct manager hook state still matches.
- `{ hostId, manager, status }` matches the same manager.
- Host manager registries/unrelated `.manager` fields do not match.
- Seven-slot atom draft identity still matches.
- Length 13/19 tuples with repeated `client-new-thread:` match.
- Draft IDs appearing once do not match.

On current Desktop, confirm `ready / request-bridge` and repeat at least one external Agent connection check. After selection, Model buttons show real Model names instead of `Models unavailable`.
