# Codex Desktop 26.814 compatibility record

This records Renderer injection and Agent/Model selection problems after a local Codex Desktop update, plus removal of obsolete compatibility code. It is not a stable internal Desktop API contract. Repeat live probes after Desktop updates.

## Observed environment

- Codex Desktop: `26.814.41407`
- Codex Framework: `151.0.7922.137`
- codex-z launch: `npm start` at repository root
- Renderer: current Codex `app://-/index.html` main window
- Fix validation date: see current workspace validation records

## User symptoms

After Desktop update:

1. Agent menu displayed, but clicks on `Claude Code`, `DeepSeek Harness`, or `Grok` did not change behavior.
2. Model button displayed `Models unavailable`.
3. Title-isolation compatibility check did not recognize the new title-service identifier.
4. Adapters sometimes showed `ready` while external Model Catalog loading failed.

These first resembled injection failure, but included independent causes.

## Causes

### 1. Request Bridge structure changed

Old codex-z used `Function.prototype.toString()` and private strings in closures to find request entries, including:

- `send-cli-request-for-host`
- `messageHandler`
- `thread-prewarm-start`
- `prewarm-thread-start-for-host`

Composer Fiber in `26.814.41407` actually contained two request-object layers:

- Outer business object: `sendRequest` only delegates to `requestClient.sendRequest(...)`.
- Actual inner Host bridge: contains `hostId: "local"`, `sendRequest`, `prewarmThreadStart`, and prototype `enqueueRequest`.

Desktop rewrote functions, so private strings were unstable. codex-z could still install startup routing and show `ready / request-bridge`. Later Model requests could not rediscover the active prewarm target when using function source.

### 2. Injection order exposed dynamic search failure

Startup order:

```text
Execute Renderer bundle
    -> Establish Agent/Model controls
Install draft routing policy
    -> Replace requestClient.sendRequest/prewarmThreadStart
Click external Agent
    -> Model client rediscovers active prewarm target
```

Policy replacement invalidates searches based on original function source. Local Agent state can change while external Catalog requests cannot reach the bridge.

Code now prefers stable API shape:

```text
hostId === "local"
has sendRequest
has prewarmThreadStart
has enqueueRequest
```

### 3. Old prewarm cleanup RPC was removed

Old Agent switching sent:

```text
clear-prewarmed-threads-for-host
```

`26.814.41407` returned:

```text
Invalid request: unknown variant `clear-prewarmed-threads-for-host`
```

This interrupted switching and caused ineffective Agent selection / `Models unavailable`.

Current cleanup uses the outer manager's lifecycle object:

```text
prewarmedThreadManager.discardAllPrewarmedThreads()
```

It uses supported `thread/delete` internally instead of the unknown RPC.

### 4. Title-service internal identifier changed

The compressed title-service identifier changed from observed `tTe` to `HTe`. After live confirmation of compatible structure, codex-z removed its identifier allowlist.

Title policy checks required service structure/methods only. Compressed-name changes no longer produce visible compatibility notices. Changed structure/method contracts still fail installation through real compatibility errors.

## Obsolete compatibility cleanup

Renderer Agent routing now uses the minimum structure confirmed in `26.814.41407`. Older Desktops missing any requirement are unsupported and reject policy installation:

- Nonempty `hostId`
- `sendRequest`
- `prewarmThreadStart`
- `enqueueRequest`
- `prewarmedThreadManager.discardAllPrewarmedThreads`

Completed cleanup:

1. Removed old Host bridge discovery through `Function.prototype.toString()`, `[[Scopes]]`, and `messageHandler`.
2. Removed old prewarm cleanup RPC fallback. `clear()` calls only `prewarmedThreadManager.discardAllPrewarmedThreads()`.
3. Removed old wrapped-prewarm/conversation argument rewriting. Creation routing handles current `thread/start` / `prewarmThreadStart` only.
4. Active request targets use API shape without function source.
5. Removed old bridge/RPC/source-feature/argument-wrapper tests; retained current structure, lifecycle cleanup, direct create, and rejection tests.
6. Updated Renderer binding documentation to stop describing removed RPC as current contract.

Other independent compatibility paths remain, including Composer identity DOM/Fiber alternatives and title-service `[[Scopes]]` inspection. They are outside this request-bridge cleanup.

Real Composer regression after cleanup still covers:

- New Threads switch from Codex to each external Agent.
- External Model Catalogs load.
- After repeated Agent switches, the next `thread/start` uses the selected Model.
- Native Codex drafts remain usable after switching back.
- Locked Threads reject incorrect Agent switching.
